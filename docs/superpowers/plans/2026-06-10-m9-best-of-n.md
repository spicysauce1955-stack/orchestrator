# M9 — best-of-n Fan-out with Judge-Based Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent step can declare `best_of: N` + `judge: <role>`: N isolated candidate implementations run, a read-only agent-as-judge scores them and selects the winner — one accountable judge with a verdict artifact, not an opaque vote (spec §4, §14 #5).

**Architecture:** Executor-level fan-out, NOT graph-level: a single `run_best_of_step` node runs N candidates by delegating to the existing `run_agent_step` with cloned steps (`<id>.cand<k>` → unique worktrees/branches/attempt keys, full success_criteria/retry per candidate), then drives the judge as one more cloned read-only agent step (`<id>.judge`, `output_schema: {winner: enum[...]}`) whose prompt carries each qualifying candidate's diff. The graph stays linear → no LangGraph parallel-state reducers, one trace per run (the M6d query invariant holds). Candidates run sequentially in MVP (concurrent `git worktree add` lock-safety unproven — noted follow-up). Disqualification: errored candidates are excluded; 0 qualifiers → error artifact; exactly 1 → wins without spending judge cost; judge error/unparseable verdict → **error step, never silent fallback** (benchmark bug #4 lesson).

**Cost accounting:** candidate/judge artifacts are recorded normally (`ctx.record` sums their cost). The final winner-clone artifact is written via `ctx.artifacts[step.id] = final` directly (NOT `ctx.record`) with `cost_usd` = sum of candidates+judge, so totals aren't double-counted. Merge safety: `run_merge_step` collects diffs only for ids in `pipeline.steps`, so `.cand<k>`/`.judge` artifacts never leak into a PR.

**Tech Stack:** Pydantic v2 (`model_copy`), existing executors/scheduler/fake-harness, pytest.
